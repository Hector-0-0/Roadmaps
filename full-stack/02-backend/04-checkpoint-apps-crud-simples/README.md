# Checkpoint 04 - Apps CRUD simples

## Objetivo del checkpoint
Crear APIs CRUD (Create, Read, Update, Delete, crear, leer, actualizar, eliminar) simples.

## Conocimientos que consolida
- [01-nodejs](../01-nodejs/README.md)
- [03-apis-restful](../03-apis-restful/README.md)

## 3 ideas de proyecto de dificultad creciente

### 1. Proyecto 1: CRUD de productos (Dificultad: básica)
**Descripción:** API para gestionar productos sin BD.

**Requisitos funcionales:**
- GET all, GET one, POST, PUT, DELETE.
- Datos en memoria/archivo JSON.
- Validación básica.

**Habilidades que practica:**
- REST, HTTP, CRUD.

**Criterios de aceptación:**
- Todos los métodos funcionan.
- Códigos correctos.
- Validación mínima.

**Mejoras opcionales:**
- Paginación.
- Filtros.

### 2. Proyecto 2: CRUD de usuarios (Dificultad: intermedia)
**Descripción:** CRUD con validación y estructura organizada.

**Requisitos funcionales:**
- Rutas separadas.
- Controladores.
- Validación de email/nombre.
- Manejo de errores.

**Habilidades que practica:**
- Organización de proyecto, validación.

**Criterios de aceptación:**
- Código modular.
- Validación funcional.
- Errores claros.

**Mejoras opcionales:**
- Middlewares.
- Logging básico.

### 3. Proyecto 3: API de tareas con estados (Dificultad: intermedia)
**Descripción:** Tareas con estados y fechas.

**Requisitos funcionales:**
- CRUD completo.
- Estados: pendiente/completado.
- Fechas de creación.
- Filtrado por estado.

**Habilidades que practica:**
- Lógica de negocio, filtros.

**Criterios de aceptación:**
- Estados funcionan.
- Filtrado correcto.
- Persistencia básica.

**Mejoras opcionales:**
- Fechas de vencimiento.
- Prioridades.
