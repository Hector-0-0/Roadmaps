# Checkpoint 09 - Trabajo colaborativo

## Objetivo del checkpoint
Practicar flujo colaborativo con Git y GitHub.

## Conocimientos que consolida
- [06-npm](../06-npm/README.md)
- [08-git-y-github](../08-git-y-github/README.md)

## 3 ideas de proyecto de dificultad creciente

### 1. Proyecto 1: Repo con README colaborativo (Dificultad: básica)
**Descripción:** Crear repo con README, .gitignore, commits organizados.

**Requisitos funcionales:**
- README con descripción.
- .gitignore.
- Al menos 3 commits con mensajes claros.
- Subir a GitHub.

**Habilidades que practica:**
- Flujo básico Git, GitHub.

**Criterios de aceptación:**
- Historial limpio.
- Archivos correctos.
- Repo público/privado según preferencia.

**Mejoras opcionales:**
- Agregar LICENSE.
- Badges.

### 2. Proyecto 2: Flujo con ramas y PR (Dificultad: intermedia)
**Descripción:** Trabajar con feature branch y simular PR.

**Requisitos funcionales:**
- Crear rama feature.
- Hacer cambios.
- Hacer push de rama.
- Crear PR en GitHub (o documentar pasos).
- Merge a main.

**Habilidades que practica:**
- Ramas, PR, merge.

**Criterios de aceptación:**
- Rama separada.
- PR documentado.
- Merge sin conflictos o resueltos.

**Mejoras opcionales:**
- Revisar diff.
- Usar plantillas.

### 3. Proyecto 3: Proyecto colaborativo simulado (Dificultad: intermedia)
**Descripción:** Simular dos contribuciones (usando dos clones o dos ramas).

**Requisitos funcionales:**
- Dos ramas con cambios distintos.
- Resolver conflicto simulado.
- Integrar ambos cambios.
- Documentar resolución.

**Habilidades que practica:**
- Conflictos, resolución, integración.

**Criterios de aceptación:**
- Conflicto identificado y resuelto.
- Código integrado funcional.
- Commits claros.

**Mejoras opcionales:**
- Usar rebase o merge según caso.
- Documentar lecciones aprendidas.
